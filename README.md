# slag.app — сайт SLAG

Публичный сайт: лендинг, документация, релизы, юридические документы и доска обращений. Отдельный
репозиторий: в приложении (`wssdozh/slag-v2`) кода сайта нет, там остаётся только переходник
`?page=landing`.

## Стек

Astro, статическая сборка, ноль клиентского фреймворка. Стили — один `src/styles/site.css` с
токенами из бренд-гайда приложения. Никаких внешних шрифтов и трекеров.

## Команды

```bash
npm install
npm run dev      # локальная разработка
npm run check    # astro check
npm run build    # тянет данные и собирает dist/
npm run preview  # посмотреть собранное
npm run data     # только обновить данные (версия, релизы, тарифы)
```

## Откуда берутся факты

Сайт не хранит у себя цифры, которые живут в другом месте:

| файл | источник | если источник недоступен |
| --- | --- | --- |
| `src/data/latest.json` | манифест `latest.json` из последнего релиза | остаётся закоммиченный снапшот |
| `src/data/releases.json` | GitHub releases API | остаётся снапшот |
| `src/data/plans.json` | `GET /api/plans` на релее (`wssdozh/slag-relay`) | остаётся снапшот |
| `public/shots/*.webp` | `scripts/landing-shots.mjs` в репозитории приложения, потом `scripts/landing-frames.sh` | файлы остаются как есть |

Поэтому `npm run build` без сети не падает: предупреждение в лог и сборка на снапшоте.
Для GitHub API полезно задать `GITHUB_TOKEN` — без него срабатывает лимит на IP и релизы
остаются снапшотом.

## Страницы

- `/` — лендинг: hero, возможности, скриншоты, «где мои данные», скачивание, тарифы, FAQ.
- `/docs` — установка, хранилище, синхронизация, MCP.
- `/releases` — заметки к релизам.
- `/privacy`, `/terms`, `/consent` — политика, соглашение, отдельное согласие на обработку данных.
- `/support` — контакты поддержки (доска обращений — следующий срез).

## Деплой

Статика кладётся на сервер рядом с релеем, раздаётся nginx по домену `slag.app`; `/api/*`
проксируется на локальный релей, поэтому запросы с сайта — same-origin. Скрипт и порядок отката —
`DEPLOY.md`.
