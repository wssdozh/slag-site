# Хранилище и файлы

## Папка, а не база

Хранилище — обычная папка. Каждая запись — файл `.md` с YAML frontmatter:

```markdown
---
id: item_1794657665638
type: task
title: Собрать структуру страницы
created: 1794657665638
folder: Проекты/Сайт
status: todo
priority: medium
tags: [сайт, дизайн]
---

- [ ] оффер
- [ ] скриншоты
```

Тип записи (`note`, `task`, `article`), папка, теги, приоритет и дедлайны живут в frontmatter, а
не в отдельном индексе. Индекс приложение строит на лету и хранит у себя — потеря индекса ничего не
ломает.

## Служебные папки

| папка | что там |
| --- | --- |
| `.attachments/` | картинки, аудио, файлы записей |
| `.trash/` | удалённые записи и вложения |

Вложения лежат рядом с заметками, поэтому копирование папки переносит всё целиком.

## Несколько хранилищ

Хранилища переключаются в сайдбаре. Каждое — своя папка со своим индексом и своими настройками
синхронизации. Разные хранилища не смешиваются даже на одном устройстве.

## Obsidian и другие редакторы

Формат совместим: открывайте папку в Obsidian, Logseq или VS Code и правьте файлы снаружи. SLAG
подхватит изменения при следующем чтении. Обратное тоже верно — то, что вы написали в SLAG, видно
любому редактору markdown.

Единственное, чего не будет снаружи: описания папок для ИИ и настройки вида. Они хранятся в служебных
файлах приложения и восстанавливаются при чтении папки.

## Корзина

Удаление — перемещение в `.trash/`. Оттуда запись можно восстановить; полная очистка корзины удаляет
файлы безвозвратно. Если папку с заметками удалили в проводнике, приложение просто увидит пустое
хранилище.

## Бэкап

Настоящий бэкап — копия папки. Приложение умеет экспортировать всё в markdown и делать полный
бэкап хранилища в JSON, но регулярную копию папки это не заменяет.
